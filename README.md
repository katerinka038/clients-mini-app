# Клиенты — Telegram Mini App

Личное приложение для учёта потенциальных клиентов: быстро добавить, сохранить контакты,
отметить статус общения, найти позже и не забыть вернуться. Плюс цифры по воронке: сколько
написала, сколько открыли, сколько ответили и что из этого вышло.

Не CRM: без рассылок, интеграций и общей базы. Цифры не хранятся отдельно — они считаются
из карточек клиентов, поэтому всегда сходятся.

---

## Что внутри

| Слой | Решение | Почему так |
| --- | --- | --- |
| Интерфейс | React 18 + TypeScript | компонентно, типы на модели данных |
| Сборка | Vite | быстрый запуск, статическая сборка в `dist` |
| Состояние | Zustand | два маленьких стора вместо контекстов и редьюсеров |
| Хранилище | Telegram CloudStorage | данные на серверах Telegram, свой бэкенд не нужен |
| Стили | обычный CSS с токенами | всю палитру можно поправить в одном файле |

Бэкенда нет намеренно. CloudStorage привязан к паре «пользователь + бот»: данные видит только
владелец, они переживают переустановку Telegram и переезд на новый телефон. Отдельная авторизация,
проверка подписи `initData` и оплата сервера при этом не нужны — Telegram делает это сам.

Ограничения платформы, о которых стоит знать: до 1024 записей, до 4096 символов на запись.
Заметка в форме ограничена 1500 символами, так что в лимит запись укладывается всегда.

**Фото клиентов** лежат отдельными записями `ph_<id>` — так картинка не съедает место
внутри карточки, а правка заметки не переписывает фото. Картинка обрезается по центру
в квадрат и сжимается до ~2,5 КБ (см. `src/domain/photo.ts`): для круга 44–56 px этого
достаточно. Каждое фото занимает одну из 1024 записей, поэтому клиенты и фото вместе
в этот лимит и укладываются. При удалении клиента фото удаляется вместе с ним.

## Экраны

1. **Клиенты** — поиск, фильтры по статусу со счётчиками, список карточек. Избранные сверху,
   дальше — недавно добавленные. Тап по тегу статуса прямо в карточке открывает нижнюю шторку
   и меняет статус, не открывая клиента. Внизу списка — выгрузка копии в CSV.
2. **Цифры** — норма дня, общая воронка и разбивка по нишам и каналам. Под каждой строкой
   подсказка, что чинить первым: канал, первые две строки или ниша. Внизу — выгрузка сводки
   таблицей, её же можно отправить куратору.
3. **Быстрое добавление** — открывается по кнопке `+`. Обязательно только название,
   поле сразу в фокусе. Всё остальное дописывается потом.
4. **Карточка клиента** — все данные, статус меняется прямо здесь одним касанием. Блок
   «Как идём» показывает канал, источник и дату первого сообщения, а отметки «прочитал»
   и «напомнила сегодня» ставятся не выходя из карточки.
   Внизу «Редактировать» и неяркое «Удалить клиента» с подтверждением.
5. **Напоминания** — «Сегодня», «Просрочено», «Позже» и «Молчат»: те, кому написала,
   а ответа так и нет.

Нижнее меню: `Клиенты | Цифры | Напоминания`, круглая кнопка `+` висит над ним справа.
На внутренних экранах меню скрывается, работает системная кнопка «назад» Telegram.

## Модель данных

```ts
interface Client {
  id: string;
  v: number;                    // версия схемы записи
  name: string;                 // единственное обязательное поле
  niche: string;
  city: string;
  site: 'yes' | 'no' | 'unknown';
  contacts: Contact[];          // тип, значение, необязательное имя
  services: string[];           // id из словаря услуг
  status: string;               // id из словаря статусов, он же шаг воронки
  note: string;

  channel: string;              // куда писали: telegram, whatsapp, vk, avito…
  source: string;               // где нашли: карты, 2ГИС, Авито, чат…
  decisionMaker: string;        // кто принимает решение
  role: string;                 // его должность
  hook: string;                 // зацепка: что у них не так
  firstTouchAt: string | null;  // дата первого сообщения, YYYY-MM-DD
  opened: boolean;              // сообщение прочитано
  pings: string[];              // даты напоминаний о себе
  amount: number;               // сумма сделки в рублях

  remindAt: string | null;      // YYYY-MM-DD
  favorite: boolean;
  createdAt: number;
  updatedAt: number;
  extra: Record<string, unknown>; // сюда попадают незнакомые поля
}
```

Три решения, которые дают запас на будущее:

- **статусы, услуги и типы контактов — строковые id** из словарей, а не жёсткий union.
  Новый статус добавляется одной строкой в `src/domain/dictionaries.ts`;
- **поле `extra`** собирает всё, чего модель не знает. Если запись сделана более новой версией
  приложения, старая версия её не испортит;
- **номер схемы `v`** — точка для будущих миграций в `normalizeClient()`.

## Как запустить локально

Нужен Node.js версии 18 или новее — на этом компьютере он пока не установлен.
Скачать: [nodejs.org](https://nodejs.org/ru) (кнопка LTS), поставить со всеми настройками
по умолчанию и перезапустить терминал.

Дальше в папке проекта:

```bash
npm install
```

```bash
npm run dev
```

Откроется адрес вида `http://localhost:5173`. В браузере приложение работает целиком,
только данные лежат в самом браузере — про это на экране есть предупреждение.

Тестовые записи: открой консоль браузера (F12) и выполни `__seedDemo()`, а для проверки
скорости — `__seedDemo(300)`. Очистить: `__clearAll()`.

Проверить типы и собрать боевую версию:

```bash
npm run build
```

Готовые файлы появятся в папке `dist`.

## Как выложить и подключить к боту

Telegram открывает Mini App только по `https`, поэтому нужен хостинг статики.
Бесплатно и быстро — Netlify, Vercel или GitHub Pages.

**Netlify, самый короткий путь:** зайти на [app.netlify.com](https://app.netlify.com),
перетащить папку `dist` в окно браузера. Через полминуты появится адрес
вида `https://имя.netlify.app`.

**Подключение к боту:**

1. В Telegram открыть [@BotFather](https://t.me/BotFather), командой `/newbot` создать бота
   (если его ещё нет).
2. `/newapp` → выбрать бота → название, описание, картинку 640 × 360 → вставить адрес сайта.
3. Там же `/mybots` → бот → *Bot Settings* → *Menu Button* → вставить тот же адрес.
   Тогда приложение будет открываться кнопкой рядом с полем ввода.

После обновления кода: `npm run build` и заново перетащить `dist` в Netlify.

**Проверка на телефоне без выкладывания:** запустить `npm run dev` и пробросить порт наружу,
например `npx localtunnel --port 5173`. Полученный `https`-адрес временно указать в BotFather.

## Как дорабатывать

**Новый статус.** В `src/domain/dictionaries.ts` дописать строку в `STATUSES`:

```ts
{ id: 'thinking', label: 'Думает', tone: 'accent' },
```

Он сам появится в фильтрах, в форме и в карточке. Уже сохранённые клиенты не пострадают.

**Новая услуга** — строка в `SERVICES`. **Новый тип контакта** — строка в `CONTACT_TYPES`.

**Новое поле клиента.** Добавить его в `Client` и в `normalizeClient()` (со значением
по умолчанию), затем вывести в форме и в карточке. Старые записи прочитаются без ошибок.

**Другие цвета.** Всё в `src/styles/tokens.css`, компоненты цветов не знают.

**Если понадобится сервер** (общий доступ, больше 1024 клиентов, файлы): интерфейс хранилища
уже отделён. Достаточно написать третью реализацию `KeyValueStorage` рядом с `cloudStorage.ts`
и подменить её в `clientsRepo.ts`. На сервере обязательно проверять подпись `initData` —
это и есть безопасная авторизация Telegram.
